# ADR-0008: Docs grow sideways

## Status
Accepted

## Date
2026-11-27

## Context
Single growing files (a DEVLOG, a decisions log, an architecture doc) become too long for people and
agents to read. They also conflict on every parallel PR when work happens in several worktrees at once.

## Decision
- History is **one file per entry** and is never rewritten: ADRs in `docs/decisions/`, devlog entries in `docs/devlog/YYYY/`.
- A changed decision gets a new ADR that supersedes the old one.
- Living docs (`PROJECT`, `GLOSSARY`, `ROADMAP`, `architecture/*`, READMEs) stay under about 300 lines and are split by area.
- Folder indexes are generated by `pnpm docs:index`.
- CI fails on an oversize living doc or a stale index.
- The detailed backlog lives in GitHub issues, and every PR closes one.

## Alternatives considered
- **Single files with discipline:** they grow anyway, and discipline does not prevent merge conflicts.
- **An external wiki:** separate from the code, so it drifts.

## Consequences
- Agents read the map, then one index, then one file.
- Parallel PRs add files instead of editing the same one.
