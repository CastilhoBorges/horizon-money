# Persistence (`apps/api/db`, `internal/port`, `internal/adapter/postgres`)

PostgreSQL 19 through pgx, with typed queries from sqlc and goose migrations embedded in the binary
(ADR-0002, ADR-0013). The design is `docs/specs/2026-11-27-persistence-design.md`.

## Files

| Path | Holds |
|---|---|
| `db/migrations/*.sql` | goose migrations, up and down; `00001_money_schema.sql` is the v0.1 money schema |
| `db/queries/*.sql` | the sqlc input, one file per aggregate |
| `db/embed.go` | `db.Migrations`, the migrations as an `embed.FS` |
| `sqlc.yaml` | sqlc settings: pgx/v5, pointers for nullable columns |
| `internal/port/repository.go` | the repository interfaces, `Store`, `Repositories` and `ErrNotFound` |
| `internal/adapter/postgres/sqlcgen/` | generated by `pnpm gen`; committed and never edited |
| `internal/adapter/postgres/postgres.go` | `Connect` (the pool), `Migrate` and `MigrateDownAll` |
| `internal/adapter/postgres/store.go` | `Store`, `InTx`, and the error handling every repository shares |
| `internal/adapter/postgres/<aggregate>.go` | users, workspaces, tags, movements, transfers and checked days |
| `internal/adapter/postgres/pgtest/` | throwaway databases for integration tests (`integration` build tag) |

## Schema in one paragraph

All ids are UUIDv7 from `uuidv7()`, and money is `bigint` minor units (ADR-0014).
- **Ownership.** Every owned table carries `user_id`. Children reference parents through
  `(parent_id, user_id)`, so the database itself refuses a row that mixes two users.
- **Movements.** One `movements` table holds one-offs and series, and a `CHECK` per kind keeps the
  repetition columns coherent. Occurrence edits live in `movement_exceptions` and
  `movement_exception_tags`.
- **Transfers.** A transfer is one row with both sides. Its workspace keys use `NO ACTION`, so a workspace
  with transfers cannot be deleted, while deleting a user still cascades.

## Repositories

- **Scoping.** Every method takes the caller's user id and filters by it. Another user's record looks
  missing: `port.ErrNotFound`.
- **Transactions.** `Store.InTx` runs several calls in one transaction for the use cases. A repository
  method that needs several statements opens its own (a savepoint inside `InTx`).
- **Errors.** `repo.done` finishes every operation's error handling in one place:
  - `ErrNotFound` and the domain's rule errors (`tag.name_taken`, `workspace.has_transfers`,
    `user.email_taken`) pass through;
  - a foreign-key violation means a referenced record is missing or another user's;
  - anything else is logged once as `postgres.<entity>.<operation>.failed`, with ids only, and returned
    wrapped.
- **Reads validate.** Rows become domain records through `Series.Validate`, so a corrupt row is an
  error, never a wrong balance.
- **Ledger reads.** `Movements.ForLedger` loads what one workspace's ledger needs: the in-range one-offs,
  every series that can produce an occurrence there, and their edits. `domain.NewLedger` turns that, the
  forecast categories and the transfers into a `Ledger`.

## Running it

| Command | Does |
|---|---|
| `horizon-money migrate` | applies pending migrations and exits (`serve` also migrates before it listens) |
| `pnpm gen` | regenerates `sqlcgen/` with the pinned sqlc image; CI fails when the output is stale |
| `pnpm test:integration` | the integration suite against `TEST_DATABASE_URL` (ADR-0015) |
| `pnpm db:worktree <slug>` | creates and migrates `horizon_<slug>` and prints its `DATABASE_URL` |

The package scripts load the repository's `.env` through `scripts/with-env.mjs`, because Turborepo does
not. Variables already in the environment win: the root `dev` and `test:integration` scripts run Turborepo
with `--env-mode=loose`, so the shell's variables reach the task.
